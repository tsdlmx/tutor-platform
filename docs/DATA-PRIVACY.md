# 个人信息处理说明（数据隐私基线）

本文件说明本系统当前代码实际收集、存储、展示与记录的个人信息，用于对齐《个人信息保护法》的最小必要、告知同意、去标识化与留存要求。**凡本文件未列出的字段，代码中不应新增采集。**

## 1. 处理者与场景

平台连接家教老师与学生/家长两类客户，并提供管理后台。个人信息处理场景只有三类：

1. 客户注册登录与身份选择（邮箱、口令、昵称、角色）。
2. 老师简历与学生需求/申请的业务内容（含老师联系方式、学生需求描述）。
3. 内容发布与审核（帖子、图片、审核意见）。

## 3. 已落实的约束

- **最小必要**：公开教师列表已移除联系电话；他人主页不再返回邮箱与最后登录时间；帖子作者名在缺少昵称时只展示邮箱前 3 位。
- **去标识化存储**：登录审计只写入掩码标识（`a***@example.com`、`adm***`），不写完整邮箱与账号名。
- **不落敏感值**：明文口令、验证码原文、JWT、会话标识均不写日志与审计；验证码只存 HMAC 摘要且一次性消费。
- **错误响应不泄露账号存在性**：登录失败统一返回"邮箱或密码错误"/"用户名或密码错误"；管理员账号被停用的提示只在口令校验通过后返回。
- **不缓存个人信息**：所有 API 响应 `Cache-Control: no-store`。
- **不向第三方共享**：除邮件服务商（投递验证码，仅传邮箱与验证码文本）外无对外共享；无跨境传输。
- **无广告/画像**：不做用户画像、不做个性化推荐所需的额外数据采集。

## 3.1 告知同意（已实现）

- 注册必须显式勾选同意，未勾选时后端直接拒绝（`400 请先阅读并同意隐私政策与用户协议`），不存在"默认同意"。
- 同意与**政策版本**一起落库到 `t_customer_consent`（账号、同意类型、`policy_version`、客户端地址、同意时间）。政策内容更新时只需提升 `PRIVACY_POLICY_VERSION`，历史记录仍指向当时生效的版本。
- `PRIVACY_POLICY_VERSION` 在生产环境为必填，缺失时服务拒绝启动——避免上线后拿不到"同意的是哪一版"的证据。
- 注册页的协议链接由构建期变量 `VITE_PRIVACY_POLICY_URL` 提供；未配置时页面只显示文字、不出死链，但勾选仍是必需项。

## 3.2 删除权（已实现）

- 客户在「我的 → 头像菜单 → 注销账号」自助注销，需重新输入登录密码确认（防误触与他人操作）。
- 注销在一个数据库事务内删除：账号、会话、简历、帖子、本人需求，以及本人发出的申请与他人对本人需求的申请；同时删除同意记录。
- 安全审计保留：`sys_login_audit` 记一条 `self_deletion`（只含掩码标识与地址），满足事后追溯而不保留可识别个人的内容。
- 删除不可恢复，页面在确认框内明确提示。

## 4. 保留与删除

- 账号存续期间保留第 2 节所列数据；客户可自助删除自己发布的帖子与简历内容。
- 客户注销：已提供自助入口（见 §3.2），无需人工介入；确需人工受理时按同一范围执行。
- 审计记录按等保要求保留 ≥ 6 个月，到期由运维归档或删除，应用不做自动清理。
- 备份中的个人信息随备份周期淘汰，需在运维侧记录备份保留期。

## 5. 客户权利响应流程（运维手册约定）

| 请求 | 处理方式 |
| --- | --- |
| 查询本人信息 | 客户在"我的"页自助查看；管理员可在客户账号页检索。 |
| 更正本人信息 | 客户自助修改昵称、简历、需求、帖子；邮箱与角色变更目前需人工处理。 |
| 删除/注销 | 客户自助注销（§3.2），立即生效且不可恢复；审计留存。 |
| 撤回同意 | 停止使用对应功能；已发布内容下架；注销即视为撤回并删除数据。 |
