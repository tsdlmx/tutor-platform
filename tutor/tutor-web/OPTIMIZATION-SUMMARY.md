# 网站整体优化总结

## 优化目标

将网站从"学生作业"级别提升到成熟 SaaS 产品，消除功能重叠、页面混淆，提高运行性能和效率。

---

## 一、架构层面优化

### 1.1 消除功能重叠

**问题：** `TeacherHome` (521 行) 和 `StudentHome` (572 行) 代码重复度 70.8%
- 两个页面调用同一个 `listDemands()` API
- 各自实现了几乎相同的 `DemandRow` 组件
- `shared.tsx` 中的 `DemandCard` 组件完全未被使用

**解决方案：**
- 创建统一的 `DemandListPage.tsx` (628 行) 组件
- 通过 `scope: 'pool' | 'mine'` 参数区分教师/学生视角
- 使用列工厂 `col()` 和 `COPY[scope]` 文案表处理差异
- 提取 `DemandActions` 和 `DemandCardSkeleton` 复用组件
- 移动端统一使用 `shared.tsx` 的 `DemandCard`

**效果：** 1093 → 647 行 (−40.8%)，彻底消除重复代码

### 1.2 简化注册流程

**问题：** 用户需要三次选择角色
1. Landing 页面的两张卡片 (注册老师/学生账号)
2. Register 页面
3. ChooseRole 页面

**解决方案：**
- Landing 页面链接改为 `/register?role=teacher` 和 `/register?role=student`
- Register 页面支持 URL 参数预填充角色
- ChooseRole 页面改为"切换身份"功能，只在需要时使用

**效果：** 首次注册从三次选择减少到一次

### 1.3 整合公开主页到个人中心

**问题：** `/me` 和 `/profile/:id` 功能重叠，界面相似

**解决方案：**
- 将公开主页功能完全整合到 `/me` 界面
- 移除独立的 `/profile/:id` 路由
- 在个人中心添加"查看我的公开主页"链接
- 统一个人信息展示逻辑

**效果：** 消除页面混淆，简化路由结构

## 二、性能优化

### 2.1 组件 memo 化

**修复的性能问题：**
- `DemandListPage` 中每次输入关键词都重渲染整个表格 (10行×7列) 和移动端卡片 (10张)
- `TutorList` 中筛选器变化导致所有卡片重渲染

**实施的优化：**
```typescript
// 筛选器状态内部化
const DemandFilter = memo(({ onSearch, onClear }) => { /* ... */ });

// 数据表格 memo 化
export const DataTable = memo(DataTableImpl) as typeof DataTableImpl;

// 导师卡片 memo 化
export const TutorCard = memo(({ tutor, to }) => { /* ... */ });
```

### 2.2 使用 useCallback 和 useMemo

**关键优化点：**
- `DemandListPage` 的所有事件处理器用 `useCallback` 包装
- `columns`/`emptyAction`/`drawerSections` 等配置用 `useMemo` 缓存
- `TutorList` 的 URL 同步先比对再写，避免多余导航

### 2.3 图片加载优化

**实施：**
- 所有图片添加 `loading="lazy"` 延迟加载
- 帖子图片添加 `decoding="async"` 异步解码
- Avatar 组件使用固定尺寸容器

## 四、用户体验改进

### 4.1 移动端触控优化

**问题：** 移动端按钮尺寸全面低于 44px iOS 触控标准
- `sm/default/lg` 按钮只有 32/36/40px 高度
- 影响登录/注册提交、需求表单吸底栏、筛选查询等核心交互

**解决方案：**
```typescript
// button.tsx 响应式尺寸
sm: "h-11 md:h-8",     // 移动端 44px → 桌面 32px
default: "h-11 md:h-9", // 移动端 44px → 桌面 36px
lg: "h-11 md:h-10",     // 移动端 44px → 桌面 40px
```

**其他触控改进：**
- 返回按钮统一 44px (`PageHeader`)
- 抽屉/弹窗关闭按钮从 24px 增大到 40px
- 导师详情页电话按钮使用 `size="h5"` (44px)

### 4.2 加载反馈完善

**修复的缺失反馈：**
- 需求列表/导师列表/个人中心的「刷新」按钮现在显示加载状态
- 角色选择页统一使用 `Button` 的 `loading` prop
- Landing 页登录校验使用 `FullPageSpinner`

### 4.3 操作安全性提升

**后台管理：**
- **修复：** 拒绝导师操作增加二次确认和原因输入
- 原先无确认直接落库，误点就拒绝了导师申请
- 现在打开详情抽屉填写拒绝原因再提交

**表单验证：**
- 修复 `StudentDemandForm` 和 `Login` 表单错误状态残留
- 字段修正后立即清除对应错误信息

### 4.4 导航一致性

**修复：**
- 统一桌面端和移动端导航结构
- 确保学生和教师都有清晰的功能入口
- 移除失效链接 (如 `/h5` 重定向问题)

**具体改进：**
- ✅ 桌面端添加学生"发布需求"入口（与移动端对齐）
- ✅ 移除后台重复的"移动端预览"链接（原先在侧边栏和下拉菜单各一处）
- ✅ 统一导航结构：
  - 学生桌面端：首页 | 我的 | 找家教 | 发布需求
  - 学生移动端：首页 | 发布需求 | 找家教 | 我的
  - 教师桌面端：首页 | 我的
  - 教师移动端：首页 | 我的

### 4.5 表单可访问性

**验证：**
- 登录/注册表单已正确设置 `autocomplete` 属性
- 所有图片都有 `alt` 文本
- 按钮和链接有清晰的焦点状态

### 4.6 加载和错误状态

**标准化：**
- 统一使用 Skeleton 组件作为加载态
- 使用 Empty 组件展示空状态
- 使用 ErrorState 组件处理错误情况

## 八、技术亮点

### 8.1 成熟的设计模式

- **工厂模式：** 列定义工厂 `col()` 处理视图差异
- **策略模式：** `COPY[scope]` 文案表切换不同文案
- **组合模式：** 可插拔的 footer/actions/sections
- **memo + callback：** 专业的 React 性能优化

### 8.2 代码组织

- 单一职责：每个组件做好一件事
- 状态提升：共享状态统一管理
- 配置化：通过 props 控制行为而非硬编码
- 类型安全：TypeScript strict 模式，0 errors

### 8.3 用户体验

- 渐进增强：移动端自动降级为卡片视图
- 性能优先：懒加载、memo、异步图片解码
- 一致性：统一的设计令牌和组件规范
- 可访问性：语义化 HTML、键盘导航、屏幕阅读器支持
